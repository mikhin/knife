# Knife

Вселенная требований, в которой можно ориентироваться. Простыни markdown
растворяются в чанках, а дубли, вода и висящие куски видны на графе — и
вычищаются вручную, потому что решение удалять принимает человек.

Требования — [docs/requirements.md](docs/requirements.md). Сценарии, которые
раньше лежали отдельным `.feature`, теперь живут исполняемыми: один файл
[tests/knife.spec.ts](tests/knife.spec.ts), где каждый тест назван своим
сценарием.

## Запуск

```sh
docker compose up -d --build     # db + linters + api + web, интерфейс на :8080
```

Разработка:

```sh
pnpm install
pnpm dev                         # поднимает Postgres, мигрирует, api :3000, web :5173
pnpm linters:up                  # если нужны Vale, textlint и proselint
```

## Что где

| Слой                    | Где             | Отвечает за                                         |
| ----------------------- | --------------- | --------------------------------------------------- |
| `apps/api`              | NestJS + Prisma | Две таблицы и ничего больше. Не считает             |
| `apps/web/src/services` | Чистые функции  | Разрез, стемминг, дубли, вода, висящие, граф, поиск |
| `apps/web/src/workers`  | Web Worker      | Держит индекс вселенной вне главного потока         |
| `services/linters`      | Docker          | Vale, textlint, proselint за одним HTTP-эндпоинтом  |

## Решения, которые стоит знать заранее

**В базе только `projects` и `chunks`.** Дубли, вода, вхождения, связи и
замечания линтеров не хранятся нигде: они считаются заново при каждом
открытии проекта. Сохранённый вердикт пережил бы формулировку, которую
судил, и через год врал бы про текст, которого уже нет.

**Считает фронт.** Бэк отдаёт чанки и проксирует линтеры. Индекс вселенной
живёт в Web Worker: 30 000 чанков проходят весь конвейер примерно за три
секунды, и это закреплено тестом `universe-scale.spec.ts`.

**Файл режется в браузере.** На сервер уходят уже готовые тексты чанков, сам
файл никуда не загружается. Markdown и plain text — разными путями:
в plain text решётка это решётка, а не заголовок.

**Чанк не правится.** В API нет ни `PATCH`, ни `PUT`, и тест это стережёт.
Не нравится формулировка — удаляешь и пишешь новую.

**Дубли считаются один раз до порога 0.25**, а ползунок фильтрует уже
готовые пары: поднять порог ничего не стоит. Кандидаты ищутся по редким
словам чанка через инвертированный индекс — иначе десятки тысяч чанков дали
бы сотни миллионов пар.

**Вода всегда называет правило.** `stop-word-flood`, `too-few-terms`,
`no-rare-terms`, `repeats-itself` — и цифры, на которых правило сработало.
Оценки «качества» одним числом здесь нет: удалять или оставить решает
человек, а для этого ему нужна причина, а не балл.

**Граф урезан честно.** Когда узлов или связей больше бюджета, интерфейс
пишет, сколько не нарисовано. Молча обрезанный граф выглядит как полный.

## Проверки

```sh
pnpm lint:check      # oxlint: sonarjs, perfectionist, boundaries, typescript
pnpm format:check    # oxfmt
pnpm tsc             # строгий TypeScript в обоих приложениях
pnpm test            # vitest: разрез, дубли, вода, висящие, поиск, нагрузка
pnpm e2e             # playwright: все сценарии целиком, через интерфейс
pnpm knip            # мёртвые файлы, экспорты, зависимости
pnpm jscpd           # копипаста
pnpm mutate          # stryker по services (не гейт, диагностика)
```

`pnpm mutate` ломает код нарочно и показывает, чего тест не заметил. Это
диагностика, а не цель: гнаться за баллом — значит писать тесты, которые
убивают мутантов и больше ничего.

```

`pnpm e2e` работает с холодного старта и ничего не просит поднять заранее:
сам запускает Postgres, заводит отдельную базу `knife_e2e`, накатывает
миграции и поднимает бэк с фронтом на своих портах (3100 и 5273). Рабочая
база при этом не трогается, а тестовая очищается перед каждым прогоном.
Чтобы пустить прогон на свою базу, задайте `E2E_DATABASE_URL` — тогда
контейнер не поднимается и данные не стираются.

Всё это же гоняется в CI отдельными джобами, чтобы имя упавшей проверки было
видно без чтения логов.

## Чего здесь сознательно нет

- правки чанков и корзины: удаление окончательное
- общего «балла качества» текста
```
